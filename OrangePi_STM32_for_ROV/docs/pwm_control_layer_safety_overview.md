

# ROV PWM 控制层：控制频率与安全保护总览

版本：v1.0  
适用工程：`pwm_control_program` / `libpwm_host` / `STM32 PWM Output`  
作者：王立，王雨舒，孙之媛 

---

## 1. 文档目的

在 ROV 中，PWM 信号直接驱动 8 路推进器 ESC 和整套大电流供电链路。  
如果 PWM 变化过快或不受控，可能导致：

- 电流瞬时冲击、母线电压剧烈波动  
- 电池 / DC-DC 保护触发，甚至掉电重启  
- ESC 过流、反向制动、温升过高  
- 推进器瞬时大推力变化，引起姿态剧烈扰动  

为避免这些风险，本项目在“上层控制算法”与“STM32 PWM 输出”之间设计了一个**独立的 PWM 控制层（`pwm_control`）**，本文件用于向新成员说明：

- PWM 控制层在整套系统中的位置  
- 为何必须做 A/B 分组分时输出  
- 控制频率的设计与要求  
- 各项安全保护机制如何工作  

---

## 2. PWM 控制层在系统中的位置

整体信号链路如下：

```text
Teleop / MPC / Auto Control（上位机控制逻辑）
                ↓
        pwm_control（本层：安全与调度）
                ↓
          libpwm_host（UDP 报文封装）
                ↓
          STM32 PWM 输出（定时器 / PWM 外设）
                ↓
           ESC（8 路） → 推进器
````

**关键认识：**

* 上层关注“控制策略、轨迹、性能”等高层目标；
* `pwm_control` 关注“安全、平滑、电气保护”，是中间的**安全缓冲层**；
* STM32 只做“按协议执行”——不再负责复杂的安全逻辑。

## 3. 控制频率（Control Frequency）

### 3.1 调用方式

`pwm_control` 自身不包含硬件定时器，而是依靠主循环周期性调用：

```c
// 例如在主循环中：
pwm_ctrl_step();   // 每 20 ms 调用一次 → 50 Hz
```

因此，**控制频率由主循环决定：**

```text
ctrl_hz = pwm_ctrl_step() 被调用的实际频率
```

推荐配置：

* 常用推荐：`ctrl_hz = 50 Hz`（每 20 ms 一步）
* 可选：`ctrl_hz = 100 Hz`（需保证主机性能和实时性）

### 3.2 为什么必须保持固定频率？

所有安全机制都依赖固定周期假设：

* 限斜率（Rate Limiter）按照“每步最多变化多少”设计；
* A/B 分组更新节奏依赖“每步切换哪个分组”；
* ESC 侧希望看到**节奏稳定、变化平滑**的 PWM 输入；
* 方便上层控制做建模、调参（每秒变化量可预测）。

如果主循环频率不稳（时快时慢）：

* “每周期固定步长”会在时间轴上变成“忽快忽慢”的实际变化；
* 推进器加速度在某些时刻突然变大；
* A/B 分组节奏失衡，供电冲击更难预测；
* 极端情况下会出现“推进器瞬时大跃变”，带来安全隐患。

**结论：**

> 主循环必须尽可能保持稳定的 real-time 调度（推荐 50 Hz），否则 `pwm_control` 的保护机制会被削弱。

## 4. A/B 通道分组与分时输出（AB Alternating Update）

### 4.1 为什么不能 8 路同时更新？

假设 8 路推进器同时从 7.5% → 9.0%：

* 8 个 ESC 同时提升输出电流 → 瞬时大电流冲击；
* 电池 / DC-DC 输出电流瞬间拉升 → 压降、保护动作、温度上升；
* 供电母线电压跌落，干扰 IMU、深度计等精密传感器；
* 推进器整体推力突增，引起 ROV 姿态和速度的异常动态响应。

在真实 ROV 工程中，这属于**重大电气与控制风险**。

### 4.2 分组策略

将 8 路 PWM 通道分为两组：

* Group A：CH1、CH2、CH3、CH4
* Group B：CH5、CH6、CH7、CH8

在 `ctrl_hz = 50 Hz` 时，内部执行逻辑示意：

```text
step 0：更新 Group A（1~4）
step 1：更新 Group B（5~8）
step 2：更新 Group A（1~4）
step 3：更新 Group B（5~8）
...
```

即：**每个控制周期只更新一组通道**。

### 4.3 工程上的保护效果

A/B 分时输出的工程意义：

* 把“8 路同时的大负载变化”拆成“两次 4 路的小负载变化”；
* 降低瞬时电流峰值，减轻电源模块与电池压力；
* 减少 ESC 同步触发过流/欠压保护的概率；
* 避免 ROV 在单个时刻承受 8 台电机同时推力变化；
* 为上层控制提供一个“缓冲层”，软化动态响应。

**本质：**

> 把一个危险的大台阶负载变成两个可控的小台阶负载。
> 这是多推进器水下机器人中非常关键、且经常被忽略的工程保护点。

## 5. PWM 控制层的安全保护机制

本控制层内集成了多种保护机制，它们共同保证推进器、电源链路以及 ROV 本体的安全。

### 5.1 占空比范围保护（Range Protection）

通过硬限制确保每路 PWM 满足：

```text
min_pct ≤ PWM ≤ max_pct
例如：5.0% ≤ PWM ≤ 10.0%，7.5% 为中位
```

作用：

* 确保所有 PWM 信号始终处于 ESC 有效范围；
* 防止上层算法 bug 让 PWM 越界，引发 ESC 自保护或异常状态。

### 5.2 限斜率（Rate Limiter）

示例配置：

```text
max_step_pct = 0.2%    // 单周期最多变化 0.2%
ctrl_hz      = 50 Hz   // 每秒 50 步
→ 最大变化速度 = 0.2% × 50 = 10% / s
```

工程效果：

* 把“不平滑的大指令”拆解成“连续的小步进序列”；
* 避免 ESC 从静止瞬间拉到高速，抑制电流尖峰；
* 减小姿态/速度的突然跃变，提高操控感和可预测性；
* 滤掉 MPC/Teleop 输出中的短时抖动或噪声。

可以理解为：**对所有 PWM 增量做了一阶低通 + 限速**。

### 5.3 反向保护（Reverse Blocking）

严禁推进器“一步反向”：

* 当前在中位以上（正转）时，若目标在中位以下（反转），不允许本周期直接越过中位；
* 必须先慢慢回到中位，再在接下来的周期里向另一侧移动；
* 从反转到正转同理。

工程意义：

* 避免 ESC 内部快速反向制动，减少大电流与发热；
* 减轻电机轴承与螺旋桨的机械冲击；
* 降低水动力瞬时扰动，防止姿态突变。

对 ROV 这种长时间连续工作的系统来说，**反向保护可以显著延长推进器和 ESC 寿命**。

### 5.4 A/B 分时输出（AB Alternation）

这一点在第 4 节已详细说明，这里只强调目标：

* 电气保护：减少瞬时总电流峰值；
* 动态保护：避免 8 通道同步跃变导致的剧烈姿态波动；
* 供电稳定：减少母线压降，保护其他传感器和计算单元。

### 5.5 平滑紧急停止（Soft Emergency Stop）

接口示例：

```c
pwm_ctrl_emergency_stop(1.0f);   // 例如在 1.0 s 内平滑回中位
```

行为特征：

* 不是“直接拉到 0”式硬急停，而是在设定时间内平滑回到 7.5% 中位；
* 减少对机械系统和电气系统的冲击；
* 即使上层逻辑崩溃或输出异常，仍可通过该接口安全收尾；
* 可映射为 Teleop 层的“急停键”（如键盘 SPACE）。

## 6. 上层控制 vs PWM 控制层：问题–保护对照表

| 上层可能出现的问题           | PWM 控制层的保护行为                    |
| ------------------- | ------------------------------- |
| MPC / Teleop 输出突然抖动 | 限斜率将大跳变拆分为小步进，自动平滑              |
| 误操作导致推进器方向瞬时反转      | 反向保护先回中位，再逐步转向另一侧               |
| 一次性让 8 路推进器同步大幅变化   | A/B 分组每次只更新 4 路，削峰填谷            |
| 算法 bug 产生越界 PWM     | 占空比范围限制将 PWM Clamp 在安全区间        |
| 程序异常 / 崩溃导致输出不可控    | Soft Emergency Stop 将所有通道平滑拉回中位 |
| 主循环频率波动导致推进器瞬时响应异常  | 限斜率 + A/B 分组在一定程度上抑制动态抖动        |

一句话总结：

> 不论上层控制是否足够成熟，`pwm_control` 都会尽最大可能确保硬件不被破坏。

## 7. 给新成员的记忆要点

对初次接触本项目的新成员，只需要牢牢记住下面几条：

1. **所有 PWM 指令都必须经过 `pwm_control`，不能直接绕过它写到 STM32。**
2. **控制频率要稳定**（推荐 50 Hz），否则限斜率和 A/B 分组的保护效果会变差。
3. **A/B 分时输出是为减轻电源冲击设计的工程机制**，不是随便写的“代码习惯”。
4. **限斜率 + 反向保护** 是用来保护 ESC 和推进器的“寿命保险”。
5. **平滑急停接口** 是实验与调试安全的最后兜底手段。

## 8. 推荐阅读顺序（Onboarding 建议）

对于刚加入项目的新成员，建议按以下顺序理解整个 PWM 控制链路：

1. 本文档：理解控制频率、A/B 分组以及所有安全保护设计。
2. `pwm_control.c`：查看实际限斜率、反向保护、A/B 调度等逻辑实现。
3. `pwm_teleop_keys.c`：了解键盘、上位机输入如何映射到目标 PWM。
4. `libpwm_host` 相关代码：理解 UDP 报文封装与主机侧通信方式。
5. STM32 端 PWM 输出代码：理解最终如何转化为定时器 PWM 信号。

理解完以上内容，新成员就可以：

* 安全地参与 Teleop / MPC 控制逻辑的开发；
* 在不破坏硬件的前提下做推进器相关实验；
* 根据需要调整限斜率、分组策略和急停时间等参数。
